# 天赋挖掘机

面向正在探索职业方向或考虑转型的人。访谈帮助来访者从具体经历中认出可迁移的做事方式，再用小实验验证职业假设。

## 使用流程

1. 阅读开场与资料处理说明，开始约 15–30 分钟的访谈。
2. 逐题回忆童年自发投入、成人后的自然胜任、做完有劲的事，以及羡慕或嫉妒。每次仅显示一个问题，回应上一个答案后再继续，四个主题都会出现，整场最多 10 题。
3. 访谈收尾时探索能力迁移和现实约束。回看或下载完整访谈。
4. 有 AI 连接时在网页生成说明书，五部分各至少 2,000 个汉字，另附完整问答，可下载 Markdown。生成中断后从上次完成的部分继续。纯静态模式可复制完整访谈和生成指令，自行交给 AI。

访谈、草稿和报告默认存储在浏览器，可通过页面清空。启用 AI 地址后，回答会发到该服务及其模型提供商。AI 服务不写入访谈文件，模型调用使用 `store: false`。提供商自身的数据保留政策仍然适用。上线前用合成资料验收，访谈中可跳过个人敏感经历。

## 在本机打开

需要 Node.js 22 或更高版本，无需安装依赖。

```bash
node server.mjs
```

打开 http://127.0.0.1:4173 。如果配置了服务端的 `OPENAI_API_KEY`，可在网页的「AI 连接设置」输入 `http://127.0.0.1:4173/api`，保存后试用 AI 访谈和说明书。

## 发布到 GitHub Pages

1. 创建公开 GitHub 仓库，将本项目源码推送到 `main` 分支。
2. 在 **Settings → Pages** 中选择 **Deploy from a branch**，分支选 `main`，目录选 `/docs`，保存。
3. 等待 Pages 部署成功，从 **Settings → Pages** 打开实际访问地址。建议用新浏览器窗口跑一遍访谈并下载记录。

Pages 托管 `docs/` 里的静态前端。无需构建，项目子路径也可运行。[GitHub Pages 发布源文档](https://docs.github.com/en/pages/getting-started-with-github-pages/configuring-a-publishing-source-for-your-github-pages-site)

## 启用网页内 AI

将可选的 `server.mjs` 部署到支持 Node.js 的服务，启动命令为 `node server.mjs`。部署源需包含 `docs/`，因为服务端共用其中的访谈规则。服务需支持 HTTPS，并允许单次请求持续约 150 秒。

| 环境变量 | 配置 |
| --- | --- |
| `OPENAI_API_KEY` | 在托管平台的密钥设置填写。避免放入前端、仓库或日志 |
| `OPENAI_MODEL` | 默认 `gpt-4.1-mini`，可按账号权限切换到支持 Responses API 的文本模型 |
| `SITE_ORIGIN` | Pages 的源，例如 `https://你的账号.github.io`，省略路径与末尾斜杠 |
| `HOST` | 托管平台需要监听外部流量时填 `0.0.0.0` |
| `PORT` | 按托管平台要求配置，默认 4173 |

将公开的 HTTPS API 地址（含 `/api`）写入 `docs/config.mjs` 的 `suggestedEndpoint`，让访客可在设置中查看地址并主动启用。保持默认空值时，访客也可自己填写地址。服务端有单实例请求频率与并发限制。公开接入付费模型前，在托管平台加部署者控制的访问与额度限制。CORS 用于浏览器跨源控制，直接调用仍需在网关防滥用。

## 验收

- 完整作答应得到 10 题，跳过主问题会省略它的追问，另外三个主题仍然出现。
- 刷新后可恢复本题及草稿。清空后回到开场。
- AI 模式用合成经历测试每轮回应、追问和报告。报告正文至少 10,000 个汉字，完整问答另计。
- 中途断开连接再恢复时，已保存的报告章节应继续保留。
